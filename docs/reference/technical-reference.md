> **For:** platform admins, developers and architects. **Kind:** reference (the low-level design).

>

This reference lists every component the three solutions contain: tables and columns, choices, flows, environment variables, connection references, security roles, prompts, the generative pages and the agent. ## 4. Flow catalogue

Times are UTC. "Ships" says whether the flow is on or off when the solution is imported: every handler ships off and is switched on with ``setup/Set-Handlers.ps1``.

| Flow | Trigger | Does | Connections and state |
|---|---|---|---|
| **assess signals** (Core) | Daily at 06:30 | Rate each exposed signal per source (generic impact from the AI hub assessment prompt + production + action date), with rationale and recommended action; never touches overrides (ADR 0010). | `crdr_dataverse`; ships on |
| **collect Dataverse detail** (Core) | Daily at 04:30 | Collect Dataverse component detail per environment as the reader app: fixture labels, maker-built code components, prompts and their models, and the flows that call them (ADR 0008 addendum 2, ADR 0013, ADR 0017). | `crdr_dataverse`; ships on |
| **collect estate inventory** (Core) | Daily at 04:00 | Collect the Power Platform estate from inventory (delegated) into crdr_asset with facets and evidence (ADR 0008). | `crdr_dataverse`, `crdr_powerplatformadmin`; ships on |
| **collect Learn page sections (feeds)** (Core) | Daily at 05:20 | Collect the active Learn page section feeds (crdr_feed kind learnpage_sections), such as the Microsoft 365 Copilot release notes: dated sections, items in scope by area or model keyword (ADR 0014). | `crdr_dataverse`; ships on |
| **collect Learn page tables (feeds)** (Core) | Daily at 05:15 | Collect the active Learn page table feeds (crdr_feed kind learnpage_tables), such as the Copilot Studio and prompt model lifecycle tables (ADR 0013, ADR 0014, spike T9). | `crdr_dataverse`; ships on |

## 7. Security roles

Privileges are at organisation level. Dataverse adds nine baseline privileges to every new role, and they are not listed: read on plug-in and SDK message metadata and on SharePoint documents and data, plus create and write on SharePoint data. They are platform defaults.

### Change Radar Admin

Runs Change Radar: full rights on every Change Radar table (settings, rules, vocabulary, feeds, watch topics, subscriptions, and the records the flows write). The connection owner whose Dataverse connection the flows use can hold this role instead of System Administrator.

| Right | Tables and components |
|---|---|
| Append | every Change Radar table (20) |
| AppendTo | every Change Radar table (20) |
| Create | every Change Radar table (20) |
| Delete | every Change Radar table (20) |
| Read | every Change Radar table (20) |
| Write | every Change Radar table (20) |

### Change Radar Reader

Change Radar read-only reader: organisation-level read on Change Radar tables.

| Right | Tables and components |
|---|---|
| Read | every Change Radar table (20), `bot`, `botcomponent`, `CanvasApp`, `connectionreference`, `msdyn_AIModel`, `Publisher`, `Solution`, `Workflow` |

### Change Radar User

Uses Change Radar: reads every Change Radar table, and changes what the pages and forms let people act on: an exposure's status (confirm or dismiss), an assessment's override, a signal's Watched flag, and a fingerprint's review status. Can't change settings, rules, vocabulary, feeds or subscriptions.

| Right | Tables and components |
|---|---|
| Read | every Change Radar table (20) |
| Write | `crdr_assessment`, `crdr_exposure`, `crdr_signal`, `crdr_signalfingerprint` |
